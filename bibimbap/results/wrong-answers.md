# BIBIMBAP 기준 ④: 틀린 답이 높은 점수를 받는가 (2026-10-09)

**방법:** 편집 과제 45개(생성·수정·삭제)마다 지시를 분명히 어긴 답안을 만들어(총 401개) 각 과제의 원 채점 스크립트로 채점했다. IfcOpenShell 0.8.3.post2(저장소 지정 버전). 각 답안이 "왜 틀렸는지"는 원본과 편집본의 모든 객체 위치 상자를 비교해 측정값으로 확인했다(`scripts/wrong/verify.py`). 원자료 `wrong-results.json`, 과제별 판정 `wrong-per-task.json`, 전체 표 `wrong-full-table.md`, 높은 점수 받은 답의 형상 근거 `wrong-flagged-evidence.md`.

- 틀린 답 401개 중 **129개가 0.9점 이상, 113개가 만점(1.0).**
- 편집 과제 45개 중 **36개에서 틀린 답이 0.9점 이상**, 34개에서 만점.
- 틀린 답을 전부 걸러 낸 과제는 없다. 0.9점 이상이 안 나온 9개는 모두 맞는 답조차 0.5점 이하인 삭제 과제이고, 그중 7개는 틀린 답이 맞는 삭제와 같은 0.5점을 받는다.

## 원인 (채점 코드 기준)
1. **무결성 검사가 다른 객체의 형상과 새로 생긴 객체를 보지 않는다.** "대상 외 객체 불변" 검사(`integrity_utils.py`)는 기존 객체의 종류·배치 행렬·속성 집합만 비교한다.
2. **이동을 형상이 아니라 배치 값으로 잰다.** 그래서 배치만 바꾸고 형상을 되돌린 "가짜 이동"이 통과한다.
3. **"닿게 하라" 검사가 편집된 기준 객체에 대해 잰다.** 대상 대신 기준을 옮겨도 통과한다.
4. **생성 과제의 위치 검사가 지시의 핵심 조건을 보지 않는다.** 높이(z), 방향, 어느 벽인지 등.
5. **삭제 하위 검사 하나가 항상 참이다.** `spatial_containment_deleted`가 원본 파일 객체와 편집 파일 객체를 직접 비교해 늘 "다르다"가 된다. 대상을 GUID로만 확인하므로 ID만 바꾼 답이 "삭제됨"으로 판정된다.

## 쓸 때 주의
- 틀린 답은 연구자가 만든 것이고, 실제 모델이 이런 답을 냈는지는 모른다(모델 결과 비공개). 주장은 "채점이 이런 답을 걸러 내지 못한다"까지.
- 일부 변형은 경계 사례(예: "2×1 m 문"을 2 m 폭으로, ±0.4 m 이내 위치 오차)라 표에서 borderline로 표시했다. 위 대표 사례는 경계 사례가 아닌 것만 골랐다.
