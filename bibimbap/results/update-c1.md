# BIBIMBAP C1 perfect-answer check: the 15 UPDATE tasks

**Setup.** For each task I built an edited IFC from the prompt and the model geometry. I did not use the test's expected values to decide the answer. Each file was scored with BIBIMBAP's own `data/tests/<name>.execute_test`, with no patches, under **ifcopenshell 0.8.3.post2**, the version `requirements.txt` pins (`ios083` copy). The score is the mean of the boolean metrics.
Scripts: `build.py` (edits), `score083.py` (scoring and diagnostics). Edited files: `out/*.ifc`. Raw metrics: `update-c1_metrics.json` (0.8.3, the primary result; same content as `update-c1_metrics_0.8.3.post2.json`) and `update-c1_metrics_0.9.0.json` (0.9.0). `run.py` is an earlier 0.9.0 emulation attempt that was replaced; only its `TARGETS` table is still used.
How the edits were made: hosted elements were moved through their opening, and the door or window follows because its placement is a child of the opening. A dimension change was made in the extrusion or profile. Shared type maps were never edited: each changed occurrence got its own copy of the geometry. `ifcopenshell.validate` reports the same number of issues before and after every edit (no new problems). Sanity check: scoring the *unedited* file never gets full marks on any task.

## Summary
- **A correct answer gets full marks on 11 of 15 tasks** under the pinned ifcopenshell 0.8.3.post2. The other 4 (test_12, geometry_test_12, geometry_test_14, topological_test_12) score 0.67, failing `right_location` each time.
- Distinct causes:
  1. **Direction convention** (test_12): "in direction of x" is scored only as −1 m (the wall's local x), not global +x.
  2. **Faulty measurement** (geometry_test_12): the wall direction is taken from the farthest vertex pair (a diagonal). After rotation it switches to the other diagonal and measures 39.2° instead of 45°.
  3. **Centre must stay fixed even though the prompt implies one end/edge moves** (geometry_test_14, topological_test_12). In topological_test_12 the only accepted answer leaves the wall detached from its column.
- Hints checked: the test_11 bbox is in world coordinates (`get_shape_vertices` applies the matrix), so a placement rotation does swap the extents → no problem. test_14 = move down: confirmed. test_13 accepts a move up as well as a resize: confirmed. topological_test_13 `right_location` is conditional, not unconditional.
- **ifcopenshell 0.9.0 (container default):** every update test raises inside `check_integrity` (`integrity_utils.py:256`, "Tree backend 'opencascade.brep' requires native brep elements"), so benchmark.py would score all 15 as 0. Separately, 0.9.0 `create_shape(settings, product)` takes the first representation ('Axis' for walls) and fails on every wall. These 0.9.0 results reflect the environment, not the tests.
- Collision semantics in 0.8.3: with the default `allow_touching=False`, faces that only touch were **not** reported. Only `allow_touching=True` reported them. That is why the "touch"/"lay on" tasks pass integrity.
