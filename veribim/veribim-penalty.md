# VeriBIM 학습 모델이 뒤집힌 삭제 채점으로 얼마나 손해를 봤나 (2026-10-09)

**자료:** VeriBIM 공개 저장소(github.com/NTUZZH/VeriBIM, 2026-10-09 clone) `results/bimedit/scores_bench_*.csv`. 6개 체크포인트(학습 전 Qwen3.5-9B + 학습본 5개), 각 324과제(삭제 108).
**방법:** VeriBIM 채점기 기록에서 삭제 과제는 `n_matched=1`이면 대상이 지워진 경우다(`veribim-overlap-check.md` 2.1 ⑦). 기록상 지운 답은 전부 의미 점수 0, 안 지운 답은 전부 1이었다(6개 모델 모두 예외 0). 삭제 과제의 의미 점수만 논문 정의대로(지웠으면 1, 아니면 0) 바꾸고, 기하·위상 점수는 그대로 두어 최종점수(세 축 평균)와 완전 해결(세 축 모두 0.98 이상)을 다시 계산했다. 스크립트 결과: `veribim_rescore.json`.

## 핵심
- **학습 효과가 가려졌다.** 학습 전 → 대표 모델(grpo_v10b_c10)의 향상폭이 공개 방식으로는 평균 +0.116, 삭제 +0.122였지만, 정정하면 평균 +0.209, 삭제 **+0.400**이다. 삭제 실력 향상의 약 70%가 성적표에서 사라졌다((0.400−0.122)/0.400).
- **학습 전 모델은 오히려 덕을 봤다.** 거의 안 지운(14/108) 학습 전 모델은 공개 방식에서 삭제 0.367을 받았지만 정정하면 0.120이다. "아무것도 안 하면 점수를 받는" 구조.
- 완전 해결 수는 공개 방식으로 0 → 10이지만 정정하면 5 → 43.
- VeriBIM 체크포인트끼리의 순위는 평균 점수 기준으로 바뀌지 않았다.

## 쓸 때 주의
- VeriBIM은 이 불일치를 알고 "공개 방식과 맞추기 위해" 일부러 유지했다고 적었다(저장소 주석). 그러므로 "VeriBIM이 잘못했다"가 아니라 "공개 방식으로 보고하면 실제 향상이 이만큼 작게 보인다"로 쓴다.
- 정정 점수는 "지웠는가"만 반영한 것이다. 다른 객체를 건드렸는지(보존)는 VeriBIM 기록의 기하·위상 점수에 맡겼다.
