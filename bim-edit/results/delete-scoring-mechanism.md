# 삭제 의미 점수는 어떻게 계산됐나: 공개 채점 기록으로 확인

확인일: 2026-10-09
질문: "수정 문제용 채점법을 삭제에도 쓴 것으로 보인다"를 확실히 알 수 있나?
자료: `실험/datasets/BIM-Edit/data/runs/<모델>/eval/eval_cache.json`(BIM-Edit-runs 공개 채점 기록), `analysis/delete_audit.csv`(우리 독립 감사), `data/tasks/tasks.jsonl`

## 결론
**추정이 아니라 공개 채점 기록에 그대로 남아 있었다.** BIM-Edit 채점기는 과제마다 `best_match_guid`(결과 파일에서 찾아낸 비교 대상 객체)와 `semantics_breakdown`(그 객체의 클래스 일치·속성 일치)을 기록한다. 삭제 과제에서도 이 값이 그대로 쓰였다.

- 결과 파일에서 비교 대상을 **찾으면**(= 대상이 안 지워짐) 클래스·속성을 비교해 의미 점수가 매겨진다.
- 비교 대상을 **못 찾으면**(= 대상이 지워짐) `best_match_guid = null`, 클래스 0·속성 0 → 의미 0.

즉 수정 과제와 같은 "찾아서 비교" 방식이 삭제 과제에 적용됐다. 원 논문 부록 E.2의 "대상이 제거되면 의미 점수를 정답으로 본다"는 예외 처리는 기록에서 보이지 않는다.

## 근거 1: 4개 모델 인공 장면 삭제 216건 (우리 감사와 대조)

| 우리 감사: 대상 | 채점기가 찾은 대상 | 의미 점수 (클래스/속성) | 건수 |
|---|---|---|---:|
| 지워짐 | 없음 (null) | 0 (0/0) | 158 (+정답 오류 과제 5) |
| 남음 | 지시 대상 그 자체 | 1 (1/1) | 40 (+정답 오류 과제 6) |
| 남음 | 지시 대상 그 자체 | **0.9 (1/0.8)** | 1 (정답 오류 과제) |
| 남음 | 없음 (null) | 0 (0/0) | 6 |

- 0.9점 사례(`claude-sonnet / ROM-DEL-SPA-A-004`)는 남은 객체의 **속성을 실제로 비교**했다는 직접 증거다. 단순히 0과 1을 뒤집은 것이라면 0.9가 나올 수 없다.

## 근거 3: 예외 6건 (안 지웠는데 0점)의 이유
6건 모두 `DOR-DEL-SPA/TOP-A-002`, `WIN-DEL-SPA-A-002`이고, 채점 기록에 **정답 객체 수 `n_gt = 0`**으로 남아 있다. 채점기가 처음부터 비교할 대상을 정하지 못한 것이다.
- 이 과제들은 2026-08 HF 토론 #2에서 **대상 GUID가 잘못됐다고 수정된 과제**다(`veribim-overlap-check.md` 2.3). 같은 객체를 쓰는 직접 지시 과제(`-DIR-A-002`)는 `n_gt = 1`로 정상 채점됐다.
- 해석(추론): 공개 채점은 GUID 수정 전 과제 파일로 돌았고, 잘못된 GUID로는 대상을 못 찾아 모델이 무엇을 하든 의미 0이 됐다. 우리 로컬 과제 파일에는 수정된 GUID만 있어 옛 GUID를 직접 대조하지는 못했다.
- 따라서 예외 6건은 "찾아서 비교" 설명과 모순되지 않는다. 오히려 **GUID 오류가 채점에도 영향을 줬다**는 별도 관찰이다.

## 논문에 쓰는 법
- 쓸 수 있음: "공개 채점 기록(eval_cache)에서 삭제 과제의 의미 점수는 결과 모델에서 비교 대상 객체가 검출된 경우에만 0보다 크며(7개 모델 756건 중 예외 없음), 대상이 제거된 경우 비교 대상이 없어 0으로 기록된다."
- 여전히 쓰지 말 것: "버그", "의도적". 채점 코드 원본은 비공개라 왜 그렇게 구현됐는지는 모른다.
- VeriBIM 설명(`config.py`의 "published runs" 주석)과도 일치한다고 함께 인용.
- VeriBIM 채점기로 재채점하는 확인은 하지 않았다. 공개 기록 자체에 비교 대상과 세부 점수가 남아 있어 더 직접적인 근거가 있기 때문이다.
